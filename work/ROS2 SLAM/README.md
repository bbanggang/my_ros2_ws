# ROS2 SLAM

## 과제 1 — Wheel Encoder의 동작원리

### SLAM에서의 역할

Wheel Encoder는 SLAM에서 **"지금까지 얼마나 움직였는가"** 를 계산하는 첫 번째 입력 소스다.  
이 값이 없으면 로봇이 자신의 위치를 추정할 기준 자체가 없다.

---

### 입력 → 처리 → 출력

```
[입력]                   [처리]                       [출력]
바퀴 회전               펄스 수 카운트                 이동 거리 / 속도
  │                        │                              │
  ▼                        ▼                              ▼
슬릿 원판이 회전  →  LED 빛이 ON/OFF 반복  →  펄스 수 × (2πr / PPR)
```


1. 바퀴에 부착된 슬릿 원판이 바퀴와 함께 회전한다.
2. LED 빛이 슬릿을 통과하면 HIGH, 막히면 LOW 펄스가 발생한다.
3. 펄스 수를 세어 **회전량**을 계산하고, 두 채널(A/B)의 위상 차로 **방향**을 판단한다.

---

## 과제 2 — Wheel Encoder Odometry의 문제점

### SLAM에서의 역할

Odometry는 Encoder 출력을 적분하여 **로봇의 현재 위치 (x, y, θ)** 를 추정한다.  
SLAM 프론트엔드의 초기 위치 추정값으로 사용되지만, 오차가 누적되는 문제가 있다.

---

**문제점 — 왜 오차가 쌓이는가:**


| 문제 | 원인 | SLAM에 미치는 영향 |
|---|---|---|
| 누적 오차(Drift) | 매 스텝 오차가 쌓임 | 장거리 이동 후 위치 추정이 실제와 크게 벗어남 |
| 바퀴 슬립 | 미끄러운 바닥에서 바퀴가 헛돔 | 펄스는 나왔지만 실제로는 이동하지 않음 |
| 바퀴 지름 오차 | 마모, 제조 공차 | 계산 거리 ≠ 실제 거리 |

**결론**

Odometry 단독으로는 오차가 발산하므로, SLAM에서는 **LiDAR/카메라 센서로 이 오차를 주기적으로 보정**한다.  
Odometry는 "대략적인 초기 위치 추정"을 제공하고, 센서 매칭이 "정확한 위치 보정"을 담당한다.

---

## 과제 3 — IMU의 동작원리

### SLAM에서의 역할

IMU는 Wheel Encoder가 잡지 못하는 **빠른 회전, 진동, 경사** 를 측정한다.  
LiDAR나 카메라의 갱신 주기 사이를 고속으로 채워 움직임 왜곡을 보정한다.

---


```
[입력]            [처리]                      [출력]
물리적 운동   →   MEMS 센서 변화량 측정   →   선형 가속도 / 각속도

```


**출력 데이터**

| 출력 | 사용처 |
|---|---|
| 각속도 (rad/s) | 짧은 시간의 회전 추정 → LiDAR 스캔 왜곡 보정 |
| 선형 가속도 (m/s²) | 속도 추정 → Wheel Odometry 보완 |
| Roll / Pitch 자세 | 경사면 주행 시 거리 오차 보정 |

→ 이 출력이 **IMU Odometry** 계산에 사용되고, 나중에 LiDAR SLAM의 움직임 보정에 활용된다.

---

## 과제 4 — IMU Odometry의 문제점

### SLAM에서의 역할

IMU는 빠른 움직임을 잘 잡지만, 단독으로 위치를 추정하면 급격히 오차가 발산한다.  
이 때문에 IMU는 항상 다른 센서와 **퓨전(Fusion)** 하여 사용한다.

---


**오차 발산 원인:**

```
작은 바이어스 오차 0.01 m/s²
  → 1초 후 속도 오차: 0.01 m/s
  → 10초 후 위치 오차: 0.5 m       (오차 ∝ 시간²)
  → 60초 후 위치 오차: 18 m       
```

**결론**

| 센서 | 장점 | 단점 |
|---|---|---|
| Wheel Encoder | 저렴, 누적 오차 선형 증가 | 바퀴 슬립, 실내 환경 의존 |
| IMU | 빠른 갱신, 3D 자세 | 누적 오차 제곱 발산 |
| **둘의 퓨전 (EKF)** | 상호 보완 | 여전히 장기 드리프트 남음 |

→ 결국 SLAM은 LiDAR/카메라 **스캔 매칭으로 누적 오차를 외부에서 보정**해야 한다.

---

## 과제 5 — SLAM에서 사용되는 센서 특징 비교

### SLAM에서의 역할

각 센서는 SLAM 파이프라인에서 서로 다른 역할을 담당한다.  
어떤 데이터를 입력받아 어떤 정보를 만들어내는지 파악하면 센서 선택의 기준이 명확해진다.

---

### 센서 특성 비교

| 항목 | 2D LiDAR | 3D LiDAR | 카메라 | IMU | Wheel Encoder |
|---|---|---|---|---|---|
| **출력 데이터** | 2D 거리 배열 | 3D 점군 | 이미지 | 가속도·각속도 | 펄스 수 |
| **갱신 주기** | 10~50 Hz | 10~20 Hz | 30~120 Hz | 100~1000 Hz | 수 kHz |
| **조명 의존** | 없음 | 없음 | 있음 | 없음 | 없음 |
| **3D 정보** | 불가 | 가능 | 가능(연산 필요) | 부분 | 불가 |
| **루프 클로저** | 가능 | 가능 | 가능 | 불가 | 불가 |
| **비용** | 중간 | 매우 높음 | 낮음 | 낮음 | 낮음 |
| **SLAM 역할** | 주력 거리 측정 | 3D 맵 작성 | 특징점 매칭 | 보조 자세 | 초기 위치 추정 |

**센서 선택 기준:**
- **실내 2D SLAM** → 2D LiDAR (낮은 비용, 신뢰성)
- **자율주행 3D SLAM** → 3D LiDAR + IMU 퓨전
- **소형 로봇/드론** → 카메라 + IMU (Visual-Inertial SLAM)

---

## 과제 6 — 필터 기반과 그래프 기반 SLAM 비교

### SLAM에서의 역할

센서에서 수집된 데이터를 받아 **"로봇이 어디에 있는가"와 "지도가 어떻게 생겼는가"** 를 동시에 추정하는 SLAM 백엔드 알고리즘이다.

---

### 필터 기반 SLAM

**핵심 아이디어**: 현재 로봇의 상태를 확률 분포로 표현하고, 새 데이터가 들어올 때마다 실시간으로 업데이트한다.


**데이터 흐름:**

```
이전 상태 → [예측 단계] → 예측 상태 → [업데이트 단계] → 보정된 상태
               ↑ 운동 모델                  ↑ 측정 모델
               (Encoder/IMU)               (LiDAR/카메라)
```

- **장점**: 데이터가 들어오는 즉시 실시간으로 처리 가능
- **단점**: 로봇이 이전에 방문한 장소(루프 클로저)를 다시 인식해도 과거의 오차를 한꺼번에 보정하기 어렵다

---

### 그래프 기반 SLAM

**핵심 아이디어**: 로봇이 지나온 모든 위치를 노드(점)로, 위치 간 관계를 엣지(선)로 표현한 그래프를 만들고, 전체를 한꺼번에 최적화한다.



**그래프 구조:**

```
  [p0] ─ 이동 ─ [p1] ─ 이동 ─ [p2] ─ 이동 ─ [p3] ─ 이동 ─ [p4]
                                                         ↑
                                루프 클로저 엣지 ─────────┘
                          (p4에서 p1과 같은 장소임을 인식)

최적화 전:  p0 ─ p1 ─ p2 ─ p3 ─ p4 (오차 누적으로 p4가 실제와 다름)
최적화 후:  루프 클로저 엣지를 포함한 전체 궤적이 동시에 보정됨
```

- **장점**: 루프 클로저 후 전체 궤적이 동시에 보정되어 정확도 우수
- **단점**: 그래프 최적화 계산이 무거워 실시간 처리에 추가 설계 필요

---

### 비교 요약

| 항목 | 필터 기반 (EKF-SLAM) | 그래프 기반 (CartographerI 등) |
|---|---|---|
| **데이터 처리 방식** | 새 데이터마다 즉시 업데이트 | 그래프 누적 후 배치 최적화 |
| **루프 클로저 보정** | 어렵고 과거 오차 수정 제한적 | 전체 궤적 동시 보정 가능 |
| **실시간성** | 우수 | 증분 최적화(iSAM2)로 해결 |
| **대규모 환경** | 어려움 | 가능 (희소 행렬 활용) |
| **ROS2 패키지** | `robot_localization` | `slam_toolbox`, `cartographer` |

## 과제 7 — 영상에서 특징점 매칭 기법

### SLAM에서의 역할

카메라 기반 SLAM(Visual SLAM)에서 **"두 시점에서 찍은 이미지의 같은 점을 찾아 카메라가 얼마나 이동했는지"** 를 계산하는 핵심 과정이다.

---

### 전체 흐름

```
[입력]          [처리 1: 검출]    [처리 2: 기술]     [처리 3: 매칭]      [출력]
이미지 A  →  특징점 위치 찾기  →  특징 벡터 생성  →  두 이미지 대응점  →  카메라 이동량
이미지 B  →  특징점 위치 찾기  →  특징 벡터 생성  →  (Homography 등)  →  (R, t 행렬)
```


---

## 과제 8 — LiDAR에서 특징점 매칭 기법

### SLAM에서의 역할

LiDAR 기반 SLAM에서 **"이전 스캔과 현재 스캔이 얼마나 겹치는지"** 를 비교하여 로봇의 이동량을 계산한다.  
카메라와 달리 색상 정보가 없으므로 **기하학적 형상(모양)** 으로 매칭한다.

---

### 전체 흐름

```
[입력]              [처리]                          [출력]
이전 LiDAR 스캔  →  기하학적 특징 추출  →  변환 행렬 (R, t)  →  로봇 이동량
현재 LiDAR 스캔  →  기하학적 특징 추출  →  (스캔이 겹치도록)  →  SLAM 포즈 업데이트
```

## 과제 9 — 변환 행렬

### SLAM에서의 역할

SLAM에는 **센서 프레임, 로봇 프레임, 월드 프레임** 등 여러 좌표계가 존재한다.  
변환 행렬은 "A 좌표계에서 본 점의 위치를 B 좌표계로 변환"하는 수학적 도구다.  
모든 센서 데이터와 로봇 위치 추정은 이 변환을 통해 하나의 공통 좌표계로 통합된다.

---

### 입력 → 처리 → 출력

```
[입력]                      [처리]                 [출력]
A 좌표계의 점 (x, y, z)  →  변환 행렬 T 곱하기  →  B 좌표계의 점 (x', y', z')
```

---

### 회전 행렬 (방향 변환)

```
2D 회전 (각도 θ 만큼):

R(θ) = [ cos θ  -sin θ ]
       [ sin θ   cos θ ]


```

---

### 동차 변환 행렬 (회전 + 이동을 하나로)

```
2D (3×3):
[ x' ]   [ cos θ  -sin θ  tx ] [ x ]
[ y' ] = [ sin θ   cos θ  ty ] [ y ]
[ 1  ]   [   0       0     1 ] [ 1 ]
  ↑          ↑    회전부분  ↑이동    ↑ 입력점

3D (4×4):
[ x' ]   [ R(3×3)  t(3×1) ] [ x ]
[ y' ] = [               ] [ y ]
[ z' ]   [  0  0  0    1  ] [ z ]
[ 1  ]                      [ 1 ]
```

- **회전 행렬 R**: 방향을 바꾼다 (크기는 유지)
- **이동 벡터 t**: 원점을 옮긴다
