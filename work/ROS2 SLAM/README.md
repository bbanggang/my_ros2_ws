# ROS2 SLAM

## SLAM 전체 흐름 개요

SLAM(Simultaneous Localization and Mapping)은 로봇이 **지도를 만들면서 동시에 자신의 위치를 추정**하는 기술이다.  
아래 흐름도에서 각 과제가 전체 파이프라인의 어느 위치에 해당하는지 먼저 파악한다.

```
┌─────────────────────────────────────────────────────────────────────┐
│                        SLAM 전체 파이프라인                           │
│                                                                     │
│  [하드웨어 센서]          [프론트엔드]            [백엔드]              │
│                                                                     │
│  Wheel Encoder  ──→  Odometry(위치 추정)  ──→                       │
│  IMU            ──→  자세 추정           ──→  포즈 그래프  ──→  지도  │
│  LiDAR          ──→  Scan Matching      ──→  최적화                 │
│  카메라          ──→  특징점 매칭         ──→  루프 클로저             │
│                                                                     │
│  과제1·2·3·4    과제5·7·8·9             과제5·6                     │
└─────────────────────────────────────────────────────────────────────┘
```

---

## 과제 1 — Wheel Encoder의 동작원리

### SLAM에서의 역할

Wheel Encoder는 SLAM에서 **"지금까지 얼마나 움직였는가"** 를 계산하는 첫 번째 입력 소스다.  
이 값이 없으면 로봇이 자신의 위치를 추정할 기준 자체가 없다.

---

### 입력 → 처리 → 출력

```
[입력]                   [처리]                       [출력]
바퀴 회전               펄스 수 카운트                 이동 거리 / 속도
  │                        │                              │
  ▼                        ▼                              ▼
슬릿 원판이 회전  →  LED 빛이 ON/OFF 반복  →  펄스 수 × (2πr / PPR)
```

**동작 원리:**

```
  [LED]  → 빛 →  [슬릿 원판]  → 빛 통과/차단 →  [수광 소자]  → HIGH/LOW 펄스
                  (바퀴에 부착)
```

1. 바퀴에 부착된 슬릿 원판이 바퀴와 함께 회전한다.
2. LED 빛이 슬릿을 통과하면 HIGH, 막히면 LOW 펄스가 발생한다.
3. 펄스 수를 세어 **회전량**을 계산하고, 두 채널(A/B)의 위상 차로 **방향**을 판단한다.

```
A채널: ▔▔╗__╔▔▔╗__   A가 B보다 앞서면 → 정방향
B채널: __╔▔▔╗__╔▔   B가 A보다 앞서면 → 역방향
```

**출력 데이터 → SLAM 연결:**

| 출력 | 단위 | SLAM에서의 사용 |
|---|---|---|
| 이동 거리 | m | 로봇이 얼마나 전진/후진했는지 계산 |
| 회전 속도 | RPM | 좌우 바퀴 속도 차로 방향 전환량 계산 |
| 방향(CW/CCW) | — | Odometry의 x, y, θ 업데이트 |

→ 이 출력이 **과제 2의 Odometry 계산**의 입력이 된다.

---

## 과제 2 — Wheel Encoder Odometry의 문제점

### SLAM에서의 역할

Odometry는 Encoder 출력을 적분하여 **로봇의 현재 위치 (x, y, θ)** 를 추정한다.  
SLAM 프론트엔드의 초기 위치 추정값으로 사용되지만, 오차가 누적되는 문제가 있다.

---

### 입력 → 처리 → 출력

```
[입력]                [처리]                        [출력]
좌/우 바퀴 펄스  →  이동량 Δd, 회전량 Δθ 계산  →  현재 위치 (x, y, θ)

x(t+1) = x(t) + Δd · cos(θ)
y(t+1) = y(t) + Δd · sin(θ)
θ(t+1) = θ(t) + Δθ
```

**문제점 — 왜 오차가 쌓이는가:**

```
실제 경로:    ────────────────────────────● (목표 지점)
Odometry:    ────────────────────────────────────────────⟋ (오차 누적)
                                              시간 →
```

| 문제 | 원인 | SLAM에 미치는 영향 |
|---|---|---|
| 누적 오차(Drift) | 매 스텝 오차가 쌓임 | 장거리 이동 후 위치 추정이 실제와 크게 벗어남 |
| 바퀴 슬립 | 미끄러운 바닥에서 바퀴가 헛돔 | 펄스는 나왔지만 실제로는 이동하지 않음 |
| 바퀴 지름 오차 | 마모, 제조 공차 | 계산 거리 ≠ 실제 거리 |

**결론 → SLAM 연결:**

Odometry 단독으로는 오차가 발산하므로, SLAM에서는 **LiDAR/카메라 센서로 이 오차를 주기적으로 보정**한다.  
Odometry는 "대략적인 초기 위치 추정"을 제공하고, 센서 매칭이 "정확한 위치 보정"을 담당한다.

## 과제 3 — IMU의 동작원리

### SLAM에서의 역할

IMU는 Wheel Encoder가 잡지 못하는 **빠른 회전, 진동, 경사** 를 측정한다.  
LiDAR나 카메라의 갱신 주기(10~30Hz) 사이를 고속(100~1000Hz)으로 채워 움직임 왜곡을 보정한다.

---

### 입력 → 처리 → 출력

```
[입력]            [처리]                      [출력]
물리적 운동   →   MEMS 센서 변화량 측정   →   선형 가속도 / 각속도

가속도계: 질량체 변위 → 정전용량 변화 → 선형 가속도 (m/s²)
자이로   : 진동체 코리올리 힘 → 정전용량 변화 → 각속도 (rad/s)
```

**구성 요소별 역할:**

```
┌──────────────────────────────────────────────────────┐
│  IMU (9-DOF)                                         │
│                                                      │
│  가속도계 (3축) → 선형 가속도 → 적분 → 속도 → 위치   │
│  자이로스코프 (3축) → 각속도 → 적분 → 자세(Roll/Pitch/Yaw) │
│  지자기 센서 (3축) → 절대 방위각 → Yaw 드리프트 보정  │
└──────────────────────────────────────────────────────┘
```

**출력 데이터 → SLAM 연결:**

| 출력 | 사용처 |
|---|---|
| 각속도 (rad/s) | 짧은 시간의 회전 추정 → LiDAR 스캔 왜곡 보정 |
| 선형 가속도 (m/s²) | 속도 추정 → Wheel Odometry 보완 |
| Roll / Pitch 자세 | 경사면 주행 시 거리 오차 보정 |

→ 이 출력이 **과제 4의 IMU Odometry** 계산에 사용되고, 나중에 LiDAR SLAM의 움직임 보정에 활용된다.

---

## 과제 4 — IMU Odometry의 문제점

### SLAM에서의 역할

IMU는 빠른 움직임을 잘 잡지만, 단독으로 위치를 추정하면 급격히 오차가 발산한다.  
이 때문에 IMU는 항상 다른 센서와 **퓨전(Fusion)** 하여 사용한다.

---

### 입력 → 처리 → 출력

```
[입력]          [처리]                          [출력]
가속도 (m/s²)  → 1차 적분 → 속도 (m/s)
               → 2차 적분 → 위치 (m)        ← 오차가 시간²에 비례해 발산
각속도 (rad/s) → 적분      → 자세 각도        ← 바이어스 드리프트로 서서히 틀어짐
```

**오차 발산 원인:**

```
작은 바이어스 오차 0.01 m/s²
  → 1초 후 속도 오차: 0.01 m/s
  → 10초 후 위치 오차: 0.5 m       (오차 ∝ 시간²)
  → 60초 후 위치 오차: 18 m        ← 사용 불가 수준
```

**결론 → SLAM 연결:**

| 센서 | 장점 | 단점 |
|---|---|---|
| Wheel Encoder | 저렴, 누적 오차 선형 증가 | 바퀴 슬립, 실내 환경 의존 |
| IMU | 빠른 갱신, 3D 자세 | 누적 오차 제곱 발산 |
| **둘의 퓨전 (EKF)** | 상호 보완 | 여전히 장기 드리프트 남음 |

→ 결국 SLAM은 LiDAR/카메라 **스캔 매칭으로 누적 오차를 외부에서 보정**해야 한다.

---

## 과제 5 — SLAM에서 사용되는 센서 특징 비교

### SLAM에서의 역할

각 센서는 SLAM 파이프라인에서 서로 다른 역할을 담당한다.  
어떤 데이터를 입력받아 어떤 정보를 만들어내는지 파악하면 센서 선택의 기준이 명확해진다.

---

### 센서별 입력·처리·출력 흐름

```
┌─────────────────────────────────────────────────────────────────┐
│  2D LiDAR                                                       │
│  입력: 레이저 360° 발사          처리: 거리 측정 (ToF)           │
│  출력: 거리 배열 (LaserScan)  →  SLAM: Scan Matching → 포즈 추정 │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  3D LiDAR                                                       │
│  입력: 다채널 레이저 (16/32/64선) 처리: 3D 거리 측정            │
│  출력: 포인트 클라우드         →  SLAM: 3D 맵 생성, 루프 클로저  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  RGB 카메라                                                     │
│  입력: 빛 (픽셀 밝기/색상)       처리: 이미지 캡처              │
│  출력: 2D 이미지              →  SLAM: 특징점 추출 → 포즈 추정  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  IMU                                                            │
│  입력: 물리적 가속/회전          처리: MEMS 정전용량 변화        │
│  출력: 가속도·각속도           →  SLAM: 스캔 왜곡 보정, 자세 추정│
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  Wheel Encoder                                                  │
│  입력: 바퀴 회전                 처리: 펄스 카운트               │
│  출력: 이동 거리·방향          →  SLAM: 초기 위치 추정(Odometry) │
└─────────────────────────────────────────────────────────────────┘
```

---

### 센서 특성 비교

| 항목 | 2D LiDAR | 3D LiDAR | 카메라 | IMU | Wheel Encoder |
|---|---|---|---|---|---|
| **출력 데이터** | 2D 거리 배열 | 3D 점군 | 이미지 | 가속도·각속도 | 펄스 수 |
| **갱신 주기** | 10~50 Hz | 10~20 Hz | 30~120 Hz | 100~1000 Hz | 수 kHz |
| **조명 의존** | 없음 | 없음 | 있음 | 없음 | 없음 |
| **3D 정보** | 불가 | 가능 | 가능(연산 필요) | 부분 | 불가 |
| **루프 클로저** | 가능 | 가능 | 가능 | 불가 | 불가 |
| **비용** | 중간 | 매우 높음 | 낮음 | 낮음 | 낮음 |
| **SLAM 역할** | 주력 거리 측정 | 3D 맵 작성 | 특징점 매칭 | 보조 자세 | 초기 위치 추정 |

**센서 선택 기준:**
- **실내 2D SLAM** → 2D LiDAR (낮은 비용, 신뢰성)
- **자율주행 3D SLAM** → 3D LiDAR + IMU 퓨전
- **소형 로봇/드론** → 카메라 + IMU (Visual-Inertial SLAM)

## 과제 6 — 필터 기반과 그래프 기반 SLAM 비교

### SLAM에서의 역할

센서에서 수집된 데이터를 받아 **"로봇이 어디에 있는가"와 "지도가 어떻게 생겼는가"** 를 동시에 추정하는 SLAM 백엔드 알고리즘이다.

---

### 필터 기반 SLAM

**핵심 아이디어**: 현재 로봇의 상태를 확률 분포로 표현하고, 새 데이터가 들어올 때마다 실시간으로 업데이트한다.

```
[입력]                    [처리]                      [출력]
센서 측정값(z)      →    예측: 운동 모델로 상태 예측   →  현재 위치 확률 분포
운동 명령(u)        →    보정: 측정값으로 분포 수정    →  (x, y, θ)의 평균·분산
                                ↓
                         EKF: 선형화(야코비안)로 근사
                         파티클 필터: 수백 개 샘플로 근사
```

**데이터 흐름:**

```
이전 상태 → [예측 단계] → 예측 상태 → [업데이트 단계] → 보정된 상태
               ↑ 운동 모델                  ↑ 측정 모델
               (Encoder/IMU)               (LiDAR/카메라)
```

- **장점**: 데이터가 들어오는 즉시 실시간으로 처리 가능
- **단점**: 로봇이 이전에 방문한 장소(루프 클로저)를 다시 인식해도 과거의 오차를 한꺼번에 보정하기 어렵다

---

### 그래프 기반 SLAM

**핵심 아이디어**: 로봇이 지나온 모든 위치를 노드(점)로, 위치 간 관계를 엣지(선)로 표현한 그래프를 만들고, 전체를 한꺼번에 최적화한다.

```
[입력]                  [처리]                         [출력]
센서 데이터 스트림  →   프론트엔드: 포즈 간 상대 변환 추정 →  포즈 그래프
                    →   루프 클로저: 같은 장소 재방문 감지  →  (노드·엣지 추가)
                    →   백엔드: 전체 그래프 최적화          →  최적 포즈 집합 + 지도
```

**그래프 구조:**

```
  [p0] ─ 이동 ─ [p1] ─ 이동 ─ [p2] ─ 이동 ─ [p3] ─ 이동 ─ [p4]
                                                         ↑
                                루프 클로저 엣지 ─────────┘
                          (p4에서 p1과 같은 장소임을 인식)

최적화 전:  p0 ─ p1 ─ p2 ─ p3 ─ p4 (오차 누적으로 p4가 실제와 다름)
최적화 후:  루프 클로저 엣지를 포함한 전체 궤적이 동시에 보정됨
```

- **장점**: 루프 클로저 후 전체 궤적이 동시에 보정되어 정확도 우수
- **단점**: 그래프 최적화 계산이 무거워 실시간 처리에 추가 설계 필요

---

### 비교 요약

| 항목 | 필터 기반 (EKF-SLAM) | 그래프 기반 (CartographerI 등) |
|---|---|---|
| **데이터 처리 방식** | 새 데이터마다 즉시 업데이트 | 그래프 누적 후 배치 최적화 |
| **루프 클로저 보정** | 어렵고 과거 오차 수정 제한적 | 전체 궤적 동시 보정 가능 |
| **실시간성** | 우수 | 증분 최적화(iSAM2)로 해결 |
| **대규모 환경** | 어려움 | 가능 (희소 행렬 활용) |
| **ROS2 패키지** | `robot_localization` | `slam_toolbox`, `cartographer` |

## 과제 7 — 영상에서 특징점 매칭 기법

### SLAM에서의 역할

카메라 기반 SLAM(Visual SLAM)에서 **"두 시점에서 찍은 이미지의 같은 점을 찾아 카메라가 얼마나 이동했는지"** 를 계산하는 핵심 과정이다.

---

### 전체 흐름

```
[입력]          [처리 1: 검출]    [처리 2: 기술]     [처리 3: 매칭]      [출력]
이미지 A  →  특징점 위치 찾기  →  특징 벡터 생성  →  두 이미지 대응점  →  카메라 이동량
이미지 B  →  특징점 위치 찾기  →  특징 벡터 생성  →  (Homography 등)  →  (R, t 행렬)
```

---

### 단계별 설명

#### 1단계: 특징점 검출 (어디서 찾을까?)

```
이미지에서 "눈에 띄는" 점을 찾는다.
코너(角), 엣지, 밝기가 급격히 바뀌는 곳이 특징점이 된다.

평탄한 영역 → 특징 없음 (위치 특정 불가)
엣지        → 1방향만 특징 있음
코너(코너점) → 모든 방향에서 특징 있음 ← 좋은 특징점
```

| 검출기 | 속도 | 스케일 불변 | SLAM 사용 |
|---|---|---|---|
| SIFT | 느림 | 있음 | 정확도 중시 |
| ORB | 매우 빠름 | 있음 | 실시간 (ORB-SLAM) |
| AKAZE | 중간 | 있음 | 균형 잡힌 선택 |

#### 2단계: 특징 기술 (이 점을 어떻게 표현할까?)

```
특징점 주변 패턴을 숫자 벡터로 표현한다.
→ 조명이 바뀌거나 각도가 달라져도 같은 점이면 벡터가 비슷해야 한다.

SIFT: 128개 실수값 벡터 (정확하지만 느림)
ORB : 256 비트 이진 벡터 (빠르고 실용적)
```

#### 3단계: 매칭 (두 이미지의 같은 점 연결)

```
이미지A의 특징점  ←→  이미지B의 특징점
벡터 거리가 가장 짧은 쌍을 매칭으로 선택

RANSAC으로 오매칭(Outlier) 제거:
→ 수학적으로 불가능한 쌍(기하학적 제약 위반)을 버린다
→ 남은 정상 매칭(Inlier)으로 카메라 이동량(R, t) 계산
```

**출력 → SLAM 연결:**

```
매칭된 대응점 집합
  → Homography / Essential Matrix 계산
  → 카메라 상대 이동 (R, t)
  → 그래프 기반 SLAM의 엣지(포즈 간 제약) 로 입력됨
```

## 과제 8 — LiDAR에서 특징점 매칭 기법

### SLAM에서의 역할

LiDAR 기반 SLAM에서 **"이전 스캔과 현재 스캔이 얼마나 겹치는지"** 를 비교하여 로봇의 이동량을 계산한다.  
카메라와 달리 색상 정보가 없으므로 **기하학적 형상(모양)** 으로 매칭한다.

---

### 전체 흐름

```
[입력]              [처리]                          [출력]
이전 LiDAR 스캔  →  기하학적 특징 추출  →  변환 행렬 (R, t)  →  로봇 이동량
현재 LiDAR 스캔  →  기하학적 특징 추출  →  (스캔이 겹치도록)  →  SLAM 포즈 업데이트
```

---

### 기법별 설명

#### ICP (Iterative Closest Point) — 점과 점을 직접 매칭

```
1. 현재 스캔의 각 점 → 이전 스캔에서 가장 가까운 점 찾기
2. 두 점군의 거리를 최소화하는 회전·이동 계산
3. 변환 적용 후 수렴할 때까지 반복

[이전 스캔] ●  ●  ●  ●  ●
[현재 스캔]   ●  ●  ●  ●  ●  ← 조금 이동된 상태
ICP 적용 후  →  두 스캔이 겹쳐짐 → 이동량(R, t) 확인
```

- **장점**: 구현이 단순, 범용적
- **단점**: 초기 위치 추정이 많이 틀리면 잘못된 곳에 수렴

#### NDT (Normal Distributions Transform) — 분포끼리 매칭

```
이전 스캔을 셀로 분할하고 각 셀을 "확률 분포(타원)"로 표현
현재 스캔의 점들이 이 분포 안에 들어오도록 변환을 최적화

[이전 스캔]   셀1의 분포   셀2의 분포   셀3의 분포
              (타원1)      (타원2)      (타원3)
[현재 스캔] 각 점 → 해당 셀 분포 안에 들어오는 확률 최대화
```

- **장점**: 점군 밀도 변화에 강인, 계산 효율 높음
- **사용처**: 자율주행 차량 위치 추정(Autoware)

#### LOAM 특징점 — 엣지와 평면으로 매칭

```
LiDAR 스캔에서 두 종류의 특징점만 추출:

곡률 높은 점 → 엣지 포인트 (벽 모서리, 물체 경계)
곡률 낮은 점 → 평면 포인트 (벽면, 바닥)

매칭: 엣지는 엣지끼리, 평면은 평면끼리 대응
→ 전체 점군의 10% 미만만 사용해도 정확한 이동량 계산 가능
→ 실시간 처리에 적합
```

#### Scan Context — 루프 클로저 감지

```
LiDAR 스캔 전체를 하나의 "장소 서명"으로 압축:

원형 스캔 → 극좌표 셀로 분할 → 각 셀의 높이 통계
→ 2D 행렬(서명) 생성

다른 시점의 서명과 유사도 비교:
→ 유사도 높음 → 같은 장소 재방문(루프 클로저) 감지
→ 그래프에 루프 클로저 엣지 추가 → 전체 궤적 보정
```

**출력 → SLAM 연결:**

```
ICP / NDT / LOAM → 로봇 이동량(R, t) → 프론트엔드 포즈 업데이트
Scan Context     → 루프 클로저 감지  → 백엔드 그래프 최적화 트리거
```

## 과제 9 — 변환 행렬

### SLAM에서의 역할

SLAM에는 **센서 프레임, 로봇 프레임, 월드 프레임** 등 여러 좌표계가 존재한다.  
변환 행렬은 "A 좌표계에서 본 점의 위치를 B 좌표계로 변환"하는 수학적 도구다.  
모든 센서 데이터와 로봇 위치 추정은 이 변환을 통해 하나의 공통 좌표계로 통합된다.

---

### 입력 → 처리 → 출력

```
[입력]                      [처리]                 [출력]
A 좌표계의 점 (x, y, z)  →  변환 행렬 T 곱하기  →  B 좌표계의 점 (x', y', z')
```

---

### 회전 행렬 (방향 변환)

```
2D 회전 (각도 θ 만큼):

R(θ) = [ cos θ  -sin θ ]
       [ sin θ   cos θ ]

예: θ = 90° → R = [ 0  -1 ]   →   x축이 y축 방향으로 회전
                   [ 1   0 ]
```

**성질**: R을 뒤집으면 역방향 회전 (Rᵀ = R⁻¹)

---

### 동차 변환 행렬 (회전 + 이동을 하나로)

```
2D (3×3):
[ x' ]   [ cos θ  -sin θ  tx ] [ x ]
[ y' ] = [ sin θ   cos θ  ty ] [ y ]
[ 1  ]   [   0       0     1 ] [ 1 ]
  ↑          ↑    회전부분  ↑이동    ↑ 입력점

3D (4×4):
[ x' ]   [ R(3×3)  t(3×1) ] [ x ]
[ y' ] = [               ] [ y ]
[ z' ]   [  0  0  0    1  ] [ z ]
[ 1  ]                      [ 1 ]
```

- **회전 행렬 R**: 방향을 바꾼다 (크기는 유지)
- **이동 벡터 t**: 원점을 옮긴다

---

### SLAM에서의 활용

```
[월드 좌표계]
     ↑
  T_base_world (Odometry가 계속 업데이트)
     ↑
[로봇 베이스]
     ↑
  T_sensor_base (URDF에 고정, 센서 장착 위치)
     ↑
[LiDAR / 카메라 프레임]
```

**변환 합성 — 센서 데이터를 월드 좌표계로 변환:**

```
p_world = T_base_world · T_sensor_base · p_sensor
            ↑                 ↑               ↑
       Odometry 위치      센서 장착 위치    센서 측정값
```

**그래프 기반 SLAM에서의 엣지:**

```
각 엣지 = 두 포즈 사이의 상대 변환 행렬 T_ij

T_ij = T_i⁻¹ · T_j   (i번 위치에서 j번 위치까지의 이동)

최적화 목표: 모든 T_ij 제약을 동시에 만족하는 {T_i} 탐색
```

---

### ROS2에서의 변환 관리 (tf2)

ROS2는 `tf2` 라이브러리로 모든 좌표 변환 트리를 자동 관리한다.

```
[map] ─── [odom] ─── [base_link] ─── [laser]
  ↑           ↑             ↑
 SLAM이 발행  Odometry가 발행  URDF에 정의
```

```python
# 변환 조회 예시
from tf2_ros import Buffer, TransformListener
tf_buffer = Buffer()
# laser 프레임의 점을 map 프레임으로 변환
transform = tf_buffer.lookup_transform('map', 'laser', rclpy.time.Time())
```
