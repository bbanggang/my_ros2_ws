# ROS2 SLAM

## 과제 1 — Wheel Encoder의 동작원리

### 개요

Wheel encoder는 바퀴의 회전을 전기 신호로 변환하여 이동 거리와 속도를 측정하는 센서다.  
크게 **증분형(Incremental)** 과 **절대형(Absolute)** 으로 나뉘며, 로봇에서는 주로 증분형 광학 엔코더 또는 자기 엔코더를 사용한다.

---

### 광학 인코더 동작 원리

```
         ┌──────────────────────────────┐
         │  디스크(슬릿 원판)              │
         │  ████░░░████░░░████░░░████   │  ← 빛을 통과시키는 슬릿(틈)
         └──────────────────────────────┘
              ↑                ↑
          발광 소자(LED)    수광 소자(포토 트랜지스터)
```

1. **디스크**에 일정 간격의 슬릿(틈)이 새겨져 있다.
2. 바퀴가 회전하면 디스크도 함께 회전한다.
3. LED 빛이 슬릿을 통과하면 **HIGH**, 막히면 **LOW** 펄스가 수광 소자에서 발생한다.
4. 발생한 펄스 수를 카운트하면 **회전각** 을 알 수 있고, 단위 시간당 펄스 수로 **각속도** 를 계산한다.

### 이동 거리 계산

```
이동 거리 D = (펄스 수 / 분해능) × 2πr
```

- **분해능(PPR, Pulses Per Revolution)**: 1회전당 발생하는 펄스 수
- **r**: 바퀴 반지름

### A/B 채널 (직교 인코더)

```
A채널: ▔▔▔╗___╔▔▔▔╗___
B채널: __╔▔▔▔╗___╔▔▔▔
       (A가 B보다 앞서면 → 정방향 회전)
       (B가 A보다 앞서면 → 역방향 회전)
```

두 채널의 위상 차이로 회전 방향까지 감지한다.

## 과제 2 — Wheel Encoder를 이용한 Odometry의 문제점

### Odometry란?

Wheel encoder 데이터를 적분하여 로봇의 위치 `(x, y, θ)` 를 추정하는 방법이다.

```
x(t+1)  = x(t)  + Δd · cos(θ)
y(t+1)  = y(t)  + Δd · sin(θ)
θ(t+1)  = θ(t)  + Δθ
```

### 주요 문제점

| 문제 | 원인 | 결과 |
|---|---|---|
| **누적 오차(Drift)** | 각 스텝의 오차가 시간에 따라 쌓임 | 장거리 이동 시 위치 추정값이 실제와 크게 벌어짐 |
| **바퀴 슬립** | 미끄러운 바닥, 급가속·급정지 시 바퀴가 미끄러짐 | 펄스는 발생하지만 실제로는 이동하지 않음 |
| **바퀴 지름 오차** | 제조 공차, 마모, 공기압 변화 | 거리 계산값과 실제 이동 거리가 달라짐 |
| **분해능 한계** | PPR이 낮으면 낮은 속도에서 정밀도 저하 | 저속 이동 시 불연속적인 위치 업데이트 |
| **미분 방정식 선형화 오차** | 불연속 적분(유한 스텝) 근사 | 고속 회전 시 각도 계산 오차 증가 |
| **실내외 환경 차이** | 바닥 재질, 경사 등 외부 요인 | 동일 명령에도 실제 이동량이 달라짐 |

### 실질적 영향

- 10m 이동 후 실제 위치와 수십 cm~수 m 오차 발생 가능
- 회전 오차 누적으로 방향 추정이 가장 빠르게 발산
- 이 때문에 단독 사용 시 대부분의 로봇 내비게이션에서 충분하지 않아 **SLAM 또는 센서 퓨전이 필수**

## 과제 3 — IMU의 동작원리

### IMU(Inertial Measurement Unit) 구성

IMU는 **가속도계(Accelerometer)** 와 **자이로스코프(Gyroscope)** 를 기본으로, 보통 **지자기 센서(Magnetometer)** 를 포함한 9축(9-DOF) 구성이 많다.

---

### 가속도계 동작 원리

```
           스프링
     ┌──[ ~~~ ]──[ 질량체 ]──[ ~~~ ]──┐
     │          →  관성력 F=ma         │
     └─────────────────────────────────┘
         정전용량 변화 → 가속도 측정
```

- MEMS(미세 전자기계 시스템) 방식: 실리콘 기판 위의 작은 질량체가 가속도에 의해 변위하면 정전용량이 바뀐다.
- 이 정전용량 변화를 전압으로 변환하여 선형 가속도를 측정한다.
- **3축(X, Y, Z)** 가속도를 동시에 측정하며, 정지 상태에서는 **중력(g ≈ 9.81 m/s²)** 도 측정된다.

### 자이로스코프 동작 원리

```
      진동하는 구조체
      ↕ (drive 방향)
      ──── 코리올리 힘 ────→ (sense 방향으로 변위)
```

- MEMS 방식: 특정 축으로 진동하는 구조체가 회전하면 **코리올리 힘(Coriolis Force)** 에 의해 수직 방향으로 변위가 발생한다.
- 이 변위량이 각속도에 비례하므로 정전용량 변화로 **각속도(rad/s)** 를 측정한다.
- **3축 각속도**를 적분하면 **자세 각도(Roll, Pitch, Yaw)** 를 추정할 수 있다.

### 지자기 센서(Magnetometer)

- 지구 자기장의 방향을 측정하여 절대적인 **Heading(Yaw)** 방향을 제공한다.
- 자이로 적분의 Yaw 드리프트를 보정하는 데 사용된다.

## 과제 4 — IMU를 이용한 Odometry의 문제점

### IMU Odometry 계산 방식

가속도를 2중 적분하여 위치를 추정한다:

```
속도: v(t+1) = v(t) + a(t) · Δt
위치: x(t+1) = x(t) + v(t) · Δt
```

### 주요 문제점

| 문제 | 원인 | 결과 |
|---|---|---|
| **바이어스 드리프트(Bias Drift)** | 자이로/가속도계의 DC 오프셋이 온도, 시간에 따라 변함 | 정지 상태에서도 각도·위치가 서서히 변함 |
| **2중 적분 오차 증폭** | 가속도 오차를 적분하면 속도 오차, 다시 적분하면 위치 오차 | 오차가 시간의 **제곱**에 비례하여 빠르게 발산 |
| **중력 성분 분리 오차** | 자세 추정 오차가 있으면 중력 성분을 정확히 제거 불가 | 수평 가속도 계산이 왜곡되어 위치 오차 가중 |
| **자이로 Yaw 드리프트** | Yaw 축 자이로는 지구 자기장으로 보정되나 실내에서 자기 간섭 | 방향 추정이 지속적으로 어긋남 |
| **고주파 진동 노이즈** | 모터 진동, 노면 충격이 가속도계에 혼입 | 저주파 필터 없이는 속도·위치 추정이 불안정 |
| **초기화 의존성** | 초기 자세·속도가 정확히 주어져야 함 | 초기 오차가 모든 이후 추정에 전파 |

### 결론

IMU 단독 Odometry는 수 초 이내의 단기 운동 추정에는 유용하지만, 장기 주행에서는 바이어스 드리프트로 인해 급격히 발산한다.  
실용적 사용을 위해 **Wheel Odometry + IMU 퓨전**(예: EKF, UKF)이 필수적이다.

## 과제 5 — SLAM에서 사용되는 센서의 특징 비교

### 주요 센서 비교표

| 항목 | 2D LiDAR | 3D LiDAR | 카메라 (RGB) | Depth 카메라 | IMU | Wheel Encoder |
|---|---|---|---|---|---|---|
| **측정 대상** | 2D 거리(단면) | 3D 포인트 클라우드 | 색상·텍스처 | RGB + 깊이 | 가속도·각속도 | 회전 펄스 |
| **출력 데이터** | 거리 배열 | 3D 점군 | 2D 이미지 | 2D+깊이 | 6-DOF 운동 | 펄스 수 |
| **갱신 주기** | 5~50 Hz | 10~20 Hz | 30~120 Hz | 30~90 Hz | 100~1000 Hz | 수 kHz |
| **정밀도** | 수 cm | 수 cm~수십 cm | 환경 의존 | 수 mm~수 cm | 단기 정밀 | 수 mm (슬립 無) |
| **환경 의존성** | 조명 무관 | 조명 무관 | 조명 민감 | 조명 일부 | 무관 | 바닥 재질 |
| **계산 비용** | 낮음 | 높음 | 중간~높음 | 중간 | 낮음 | 매우 낮음 |
| **비용** | 중간 | 매우 높음 | 낮음 | 중간 | 낮음~중간 | 낮음 |
| **3D 맵 작성** | 불가(2D만) | 가능 | 가능(VI-SLAM) | 가능 | 불가 | 불가 |
| **루프 클로저** | 가능 | 가능 | 가능(특징점) | 가능 | 불가 | 불가 |
| **야외 사용** | 가능 | 가능 | 제한적 | 제한적(햇빛) | 가능 | 가능 |

---

### 센서별 특징 상세

#### 2D LiDAR
- 레이저 펄스를 360° 회전하며 조사하여 단면 거리 데이터를 획득한다.
- GMapping, Cartographer, Hector SLAM 등의 2D SLAM에서 주력 센서로 사용된다.
- 동일 평면의 장애물만 감지하므로 발 아래 장애물이나 천장 구조는 인식 불가능하다.
- **강점**: 높은 신뢰성, 낮은 계산 비용, 조명 무관

#### 3D LiDAR
- 여러 채널(16, 32, 64, 128선)의 레이저로 3D 포인트 클라우드를 생성한다.
- LOAM, LeGO-LOAM, LIO-SAM 등 3D LiDAR SLAM에서 핵심 센서다.
- 가격이 수백~수천만 원대로 매우 비싸다.
- **강점**: 정밀한 3D 맵, 장거리 감지(100m+), 날씨·조명 무관

#### RGB 카메라
- 색상과 텍스처 정보가 풍부하여 특징점 기반 루프 클로저에 유리하다.
- ORB-SLAM2/3, DSO 등의 Visual SLAM에 사용된다.
- **단점**: 조명 변화와 빠른 움직임(Motion Blur)에 취약하다.

#### Depth 카메라 (RGB-D)
- Intel RealSense, Microsoft Kinect 등이 대표적이다.
- 구조광 또는 ToF 방식으로 각 픽셀의 깊이를 측정한다.
- **단점**: 야외(직사광선)에서 IR 간섭으로 깊이 측정 불가, 감지 범위 제한(0.5~5m)

#### IMU
- 매우 높은 갱신 주기로 짧은 시간 동안 정밀한 운동 추정이 가능하다.
- LiDAR나 카메라 SLAM에서 운동 왜곡 보정(Motion Distortion Correction)에 활용된다.
- LiDAR-IMU 퓨전(LIO-SAM), Visual-IMU 퓨전(VINS-Mono)이 대표적이다.

## 과제 6 — 필터 기반과 그래프 기반 SLAM의 비교

### 개요

| 항목 | 필터 기반 SLAM | 그래프 기반 SLAM |
|---|---|---|
| **핵심 아이디어** | 현재 상태를 확률 분포로 유지, 재귀적 업데이트 | 포즈·랜드마크를 노드로 하는 그래프 최적화 |
| **대표 알고리즘** | EKF-SLAM, UKF-SLAM, FastSLAM(파티클 필터) | GraphSLAM, iSAM, g2o, GTSAM |
| **ROS2 패키지** | `robot_localization` (EKF) | `cartographer`, `rtabmap`, `slam_toolbox` |
| **계산 복잡도** | O(N²) ~ O(N) (N: 랜드마크 수) | O(N) ~ O(N log N) 희소 행렬 활용 시 |
| **메모리 사용** | 공분산 행렬이 크기 증가 | 그래프 노드+엣지 저장 (희소) |
| **실시간 처리** | 적합 (재귀 업데이트) | 백엔드 최적화는 오프라인 가능 |
| **루프 클로저** | 어렵고 오차 전파 | 자연스럽게 전체 궤적 보정 |
| **확장성** | 환경 크기 제한 있음 | 대규모 환경에 유리 |

---

### 필터 기반 SLAM

#### EKF-SLAM (Extended Kalman Filter)

```
[예측 단계]
  x̂(t|t-1) = f(x̂(t-1), u(t))      ← 운동 모델로 상태 예측
  P(t|t-1) = F·P(t-1)·Fᵀ + Q       ← 공분산 예측

[업데이트 단계]
  K = P·Hᵀ·(H·P·Hᵀ + R)⁻¹         ← 칼만 게인
  x̂(t) = x̂(t|t-1) + K·(z - h(x̂)) ← 관측으로 상태 보정
```

- 비선형 운동 모델을 **테일러 1차 선형화(야코비안)** 로 근사한다.
- 상태 벡터: `[로봇 포즈 | 랜드마크 위치]` — 랜드마크 수가 늘면 행렬 크기가 급격히 커진다.
- **장점**: 연속적인 상태 추정, 측정 불확실성을 공분산으로 모델링
- **단점**: 비선형성이 강할수록 선형화 오차 증가, O(N²) 복잡도로 대규모 환경 부적합

#### FastSLAM (파티클 필터 기반)

- 로봇 궤적을 파티클(샘플)들로 표현하고, 각 파티클마다 독립적인 EKF 랜드마크 맵을 유지한다.
- O(M log N) (M: 파티클 수, N: 랜드마크 수)로 EKF-SLAM보다 효율적이다.
- **단점**: 파티클 수가 많아야 정밀도 유지, 고차원 상태에서는 파티클 부족 문제

---

### 그래프 기반 SLAM

#### 구조

```
  포즈 그래프:
  [p0] ─ 이동 엣지 ─ [p1] ─ 이동 엣지 ─ [p2] ─ ... ─ [pN]
           ↑                                    ↑
     루프 클로저 엣지 ─────────────────────────────
```

- **노드(Vertex)**: 로봇이 방문한 각 포즈 `(x, y, θ)` 또는 랜드마크
- **엣지(Edge)**: 두 노드 간의 상대적 변환 제약 조건 (측정값 + 불확실성)
- **목표**: 모든 엣지 제약을 만족하는 최적 포즈 집합을 찾는 비선형 최소제곱 최적화

```
최적화 목표: argmin Σ ||z_ij - h(x_i, x_j)||²_Ω
```

#### 프론트엔드 vs 백엔드

| 역할 | 내용 |
|---|---|
| **프론트엔드** | 센서 데이터로 포즈 간 상대 변환 추정 (Scan Matching, 특징점 매칭) |
| **백엔드** | 포즈 그래프를 Gauss-Newton, Levenberg-Marquardt로 최적화 |

- **장점**: 루프 클로저 감지 후 전체 궤적이 동시에 보정됨, 희소 행렬 활용으로 대규모 환경 가능
- **단점**: 배치 최적화는 실시간 처리 어려움 (증분 최적화 iSAM2로 해결)

## 과제 7 — 영상에서 특징점 매칭 기법의 종류와 기능

### 특징점 매칭 파이프라인

```
이미지 A ──→ [특징점 검출] ──→ [특징 기술자 계산] ──→ [매칭] ──→ 대응점 집합
이미지 B ──→ [특징점 검출] ──→ [특징 기술자 계산] ──→ [매칭] ─┘
```

---

### 특징점 검출기 (Detector)

#### Harris Corner Detector
- 이미지의 국소 영역에서 모든 방향으로 밝기 변화가 큰 점(코너)을 검출한다.
- **이미지 구조 텐서(2차 모멘트 행렬)** 의 고유값 분석으로 코너·엣지·평탄 영역을 구분한다.
- 스케일 변화에 취약하다.

#### SIFT (Scale-Invariant Feature Transform)
- DoG(Difference of Gaussian) 피라미드로 **스케일 공간** 을 구성하여 스케일 불변 특징점을 검출한다.
- 128차원 기술자는 회전·스케일·조명 변화에 강인하다.
- **장점**: 높은 매칭 정확도 / **단점**: 계산 비용이 높아 실시간 처리 어려움 (특허 만료로 현재는 자유 사용)

#### SURF (Speeded-Up Robust Features)
- SIFT를 가속화한 버전으로, DoG 대신 **Hessian 행렬 근사** 와 Haar Wavelet 기술자를 사용한다.
- SIFT보다 3~7배 빠르나 여전히 계산 부담이 있다.

#### ORB (Oriented FAST and Rotated BRIEF)
- **FAST** 코너 검출 + **BRIEF** 이진 기술자의 회전 불변 버전이다.
- 이진 기술자(256 bit)라 **Hamming Distance** 로 빠르게 매칭 가능하다.
- 실시간 Visual SLAM(ORB-SLAM2/3)의 핵심 특징점이다.
- **장점**: 매우 빠름, 특허 없음 / **단점**: 스케일 변화에 SIFT보다 다소 취약

#### AKAZE / KAZE
- 비선형 스케일 공간(Nonlinear Scale Space)을 사용하여 물체 경계를 더 잘 보존한다.
- KAZE보다 AKAZE가 훨씬 빠르며 이진 기술자를 지원한다.

---

### 특징 기술자 (Descriptor)

| 기술자 | 유형 | 차원 | 특징 |
|---|---|---|---|
| SIFT | 실수 벡터 | 128D | 회전·스케일·조명 불변, 높은 정확도 |
| SURF | 실수 벡터 | 64D | SIFT보다 빠름 |
| ORB | 이진 | 256 bit | 매우 빠름, Hamming 거리 매칭 |
| BRIEF | 이진 | 256 bit | 회전 비불변, 빠름 |
| BRISK | 이진 | 512 bit | 스케일·회전 불변, 빠름 |

---

### 매칭 방법

#### Brute-Force Matching
- 한 이미지의 각 특징점 기술자를 다른 이미지의 모든 기술자와 비교하여 가장 거리가 짧은 것을 매칭한다.
- 실수 기술자: **유클리드 거리**, 이진 기술자: **Hamming 거리** 사용
- **Lowe's Ratio Test**: 최근접 거리 / 2순위 거리 < 0.75 이면 좋은 매칭으로 판정

#### FLANN (Fast Library for Approximate Nearest Neighbors)
- KD-Tree 또는 LSH(Locality Sensitive Hashing) 자료구조로 근사 최근접 탐색을 수행한다.
- Brute-Force보다 빠르나 정확도가 약간 낮다.

#### RANSAC (RANdom SAmple Consensus)
- 매칭된 특징점 쌍에서 오매칭(Outlier)을 제거하는 기법이다.
- 무작위로 최소 샘플을 뽑아 모델(Homography, Fundamental Matrix)을 추정하고, 그 모델을 지지하는 점(Inlier)이 가장 많은 모델을 선택한다.
- **기능**: 노이즈와 오매칭이 많은 실제 환경에서 신뢰할 수 있는 변환 추정을 가능하게 한다.

## 과제 8 — LiDAR에서 특징점 매칭 기법의 종류와 기능

### LiDAR 포인트 클라우드의 특성

카메라와 달리 색상·텍스처 정보가 없고 **기하학적 형상(3D 좌표)** 만 존재한다.  
따라서 기하학적 구조를 기반으로 한 매칭 기법이 사용된다.

---

### ICP (Iterative Closest Point)

```
알고리즘 흐름:
1. 소스 포인트 클라우드의 각 점에 대해 타겟에서 가장 가까운 점을 찾는다.
2. 대응점 쌍의 거리를 최소화하는 변환 (R, t)를 계산한다.
3. 소스 클라우드를 변환 적용 후 수렴할 때까지 반복한다.
```

- **Point-to-Point ICP**: 대응점 간 유클리드 거리를 최소화한다.
- **Point-to-Plane ICP**: 소스 점과 타겟의 접평면 사이 거리를 최소화한다. 수렴이 빠르고 곡면에 강인하다.
- **단점**: 초기 위치 추정이 나쁘면 지역 최적해에 빠진다. 실시간 처리에 계산 비용이 높다.

---

### NDT (Normal Distributions Transform)

```
알고리즘 흐름:
1. 타겟 포인트 클라우드를 규칙적인 셀로 분할한다.
2. 각 셀의 점들을 정규분포(평균, 공분산)로 모델링한다.
3. 소스 점들이 이 분포에서 나타날 확률을 최대화하는 변환을 탐색한다.
```

- 포인트 대신 **확률 분포** 끼리 매칭하므로 포인트 밀도 변화에 강인하다.
- Autoware 자율주행 스택에서 LiDAR 위치 추정에 사용된다.
- **장점**: ICP보다 계산 효율이 높고 노이즈에 강인 / **단점**: 셀 크기 선택이 성능에 영향

---

### LOAM 계열 특징점 (엣지·평면)

LOAM (LiDAR Odometry and Mapping)에서 제안된 기하학적 특징점:

```
곡률(curvature) 계산:
c = (1/|S|·||Δp||) · || Σ_{i∈S} (p_i - p) ||

c가 크면 → 엣지(Edge) 특징점
c가 작으면 → 평면(Planar) 특징점
```

| 특징 유형 | 검출 기준 | 매칭 방법 |
|---|---|---|
| **엣지 포인트** | 곡률 높음 (모서리, 경계) | 가장 가까운 엣지 라인과 점-직선 거리 최소화 |
| **평면 포인트** | 곡률 낮음 (벽, 바닥) | 가장 가까운 평면과 점-평면 거리 최소화 |

- 스캔 당 소수의 특징점만 사용하므로 ICP보다 훨씬 빠른 실시간 처리가 가능하다.
- **LeGO-LOAM, LIO-SAM** 등 후속 알고리즘에서도 동일한 특징점 개념을 사용한다.

---

### Scan Context (루프 클로저 기술자)

```
극좌표 분할:
     360°
      ↑
  R ─┼── 거리 방향
      └─ 각도 방향
각 셀의 최대 높이값으로 2D 서명 행렬 생성
```

- 포인트 클라우드를 극좌표로 분할하고 각 셀의 통계(최대 높이 등)를 집계하여 **장소 서명(Place Signature)** 을 생성한다.
- 두 서명 행렬의 컬럼 시프트 + 코사인 거리로 장소 유사도를 계산한다.
- **기능**: 루프 클로저 감지 — 로봇이 이전에 방문한 장소를 인식하여 누적 오차를 보정한다.

---

### LiDAR 매칭 기법 비교

| 기법 | 입력 | 특징 | 주 용도 |
|---|---|---|---|
| ICP | 점군 | 간단, 초기값 민감 | 단거리 포즈 정제 |
| NDT | 점군→분포 | 노이즈 강인 | 자율주행 위치추정 |
| LOAM 특징점 | 엣지/평면점 | 빠름, 실시간 | LiDAR Odometry |
| Scan Context | 전체 스캔 서명 | 장소 인식 | 루프 클로저 |

## 과제 9 — 회전 이동과 평행 이동을 정의하는 변환 행렬

### 좌표 변환의 필요성

SLAM에서 센서 프레임, 로봇 프레임, 월드 프레임 간 좌표 변환이 지속적으로 필요하다.  
ROS2에서는 `tf2` 라이브러리가 이 변환 트리를 관리한다.

---

### 2D 변환 (SE(2))

#### 2D 회전 행렬

각도 θ 만큼 반시계 방향으로 회전:

```
R(θ) = [ cos θ  -sin θ ]
       [ sin θ   cos θ ]
```

- 행렬식: det(R) = 1
- 역행렬 = 전치행렬: R⁻¹ = Rᵀ (직교 행렬)

#### 2D 평행 이동 + 회전 (동차 좌표계)

```
[ x' ]   [ cos θ  -sin θ  tx ] [ x ]
[ y' ] = [ sin θ   cos θ  ty ] [ y ]
[ 1  ]   [   0       0     1 ] [ 1 ]
```

- 3×3 동차 변환 행렬(Homogeneous Transformation Matrix)로 회전과 이동을 하나의 행렬 곱으로 표현한다.
- **tx, ty**: 평행 이동 벡터

---

### 3D 변환 (SE(3))

#### 3D 회전 행렬 (SO(3))

X, Y, Z 축 기본 회전:

```
Rx(α) = [ 1    0      0   ]    (Roll)
        [ 0  cos α  -sin α ]
        [ 0  sin α   cos α ]

Ry(β) = [ cos β   0  sin β ]   (Pitch)
        [   0     1    0   ]
        [-sin β   0  cos β ]

Rz(γ) = [ cos γ  -sin γ  0 ]   (Yaw)
        [ sin γ   cos γ  0 ]
        [   0       0    1 ]
```

- 일반 3D 회전: **R = Rz(γ) · Ry(β) · Rx(α)** (ZYX Euler 순서, 로봇 공학 표준)
- 3×3 회전 행렬의 성질: Rᵀ = R⁻¹, det(R) = 1

#### 3D 동차 변환 행렬 (4×4)

```
T = [ R₃ₓ₃  t₃ₓ₁ ] = [ r₁₁ r₁₂ r₁₃  tx ]
    [  0    1    ]   [ r₂₁ r₂₂ r₂₃  ty ]
                     [ r₃₁ r₃₂ r₃₃  tz ]
                     [  0   0   0    1  ]
```

- **R**: 3×3 회전 행렬
- **t**: 3×1 평행 이동 벡터
- 점 변환: `p' = T · p` (동차 좌표 `p = [x, y, z, 1]ᵀ`)

---

### 변환 행렬의 합성

연속된 좌표 변환은 행렬 곱으로 합성된다:

```
T_AC = T_AB · T_BC
```

- `T_AB`: 프레임 B를 프레임 A로 표현하는 변환
- **순서 중요**: 행렬 곱은 교환 법칙이 성립하지 않는다.

### 역변환

```
T⁻¹ = [ Rᵀ  -Rᵀ·t ]
      [  0     1   ]
```

- 회전 역변환은 전치(Rᵀ), 이동 역변환은 `-Rᵀ·t`

---

### 회전 표현 방법 비교

| 표현 방법 | 파라미터 수 | 특징 |
|---|---|---|
| **회전 행렬 R** | 9개 (제약 6개) | 합성이 행렬 곱, 짐벌락 없음 |
| **오일러 각 (Roll/Pitch/Yaw)** | 3개 | 직관적이나 짐벌락(Gimbal Lock) 문제 |
| **축-각 표현 (Axis-Angle)** | 4개 | 보간에 유리 |
| **쿼터니언 (Quaternion)** | 4개 (단위 제약) | 짐벌락 없음, 보간 용이, ROS2 표준 |

ROS2의 `geometry_msgs/msg/Pose`는 위치(Point)와 자세(Quaternion)를 사용한다.

```python
# ROS2 tf2에서 변환 예시
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped

t = TransformStamped()
t.transform.translation.x = tx
t.transform.rotation.w = q_w  # 쿼터니언
```

---

### SLAM에서의 활용

```
[센서 프레임] ──T_sensor_base──> [로봇 베이스] ──T_base_world──> [월드 프레임]
                   (정적, URDF)                   (동적, Odometry)
```

- 그래프 기반 SLAM의 각 엣지는 두 포즈 사이의 **상대 변환 행렬** `T_ij`로 표현된다.
- 최적화 목표: 모든 `T_ij` 제약을 최대한 만족하는 절대 포즈 집합 `{T_i}` 를 탐색한다.
